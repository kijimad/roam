KDOC 183: イメージビルド時にツール側のキャッシュを使う

概要

Docker imageをビルドするときレイヤーキャッシュが生成されるが、ファイル内容に違いがあると破棄されてビルドが再実行される。なのでコードが1行でも、依存ライブラリが1行でも変更されると、ゼロからビルドして時間がかかることになる。コンパイラのビルドキャッシュ/パッケージ管理ツールのインストールキャッシュを利用するには、専用の領域を指定して保存しておく。 

# Dockerfile
RUN --mount=type=cache,target=/go/pkg/mod \
    --mount=type=cache,target=/root/.cache/go-build \
    --mount=type=bind,target=. \
    go build .

これによって、2段階のキャッシュを利用することになる。

  1. 内容が全く同じ場合はDockerのレイヤーキャッシュを使う
  2. 内容が変わった場合はマウントしたモジュールキャッシュとコンパイラのビルドキャッシュを使う

となり、高速化できる。

関連

抽象。

  • わずかな変更でも、粗い単位のキャッシュはまるごと無効になる
  • 粗いキャッシュが外れたときに、細かい単位のキャッシュで受け止める多段構成

関連。

  • 追加調査: Docker の mount type の違いを調べる
