メモを校正する。指摘は会話に流さず、**対象ファイルの該当行の直下に `#` コメントで書き込む**。昇格時の「すべてのコメントを削除した」で消えるので、レビューは draft の間だけ生きる。

基準の正典は [`CLAUDE.md`](../../../CLAUDE.md)。ここは適用手順だけを持つ。

## 手順

1. **対象を決める。** 引数のファイル、無ければ**リポジトリ全体で**ファイル名に `draft` を含む `.org`(例 `draft_permanent`)を対象にする(git 差分の有無は問わない)。次で列挙する:

   ```sh
   find . -name '*draft*.org' -not -path './.git/*' | sort
   ```

   draft の間にレビューし、昇格(ファイル名から `draft` が外れる)で対象から外れる
2. **事実を正典で検証。** load-bearing な主張は記憶で判定しない。`docs-anchor` の registry で正典(URL+版+節)を辿る。normative と inferred を混ぜない。確定できないものは「未確認」。
3. **基準を確認。** 3回/10分/驚きのどれかを満たすか。満たすなら核心("へぇ"の中身)が書けているか。
4. **フォーマットを確認。** 1メモ1事実か / 疑問と答えは別ファイルか / 自分の言葉で文脈なく読めるか(差は「向き」まで) / 関連リンクか将来の切り口があるか。
5. **書き込む。** 各指摘を該当行の直下に:
   ```
   # [レビュー:<カテゴリ>] <一文>。
   #   <続き・根拠・修正案>
   ```
   カテゴリ: 事実 / 用語 / 精度 / フォーマット / 関連 / 基準 / 任意。`事実` は正典アンカーを添える。合否の総括だけ会話に日本語で返す。
6. **textlint を対象ファイルだけにかける。** 全 `.org` ではなく、手順1で決めた対象のみ。`FILES` に対象を渡す:

   ```sh
   make textlint FILES="./<対象1>.org ./<対象2>.org"
   ```

   日本語の文章規則(`ja-technical-writing`: 助詞の連続、漢数字、二重否定など)の指摘が出たら、意味を変えない範囲で本文を直す。校正コメント(`#` 行)は対象外なので触らない。`FILES` 未指定だと全ファイルを舐めるので必ず指定する。終了コード 0 を確認して総括に含める。

## 連携

- 正典検証 → `docs-anchor`
- 理解度を試す → `reverse-questions` / `grill-me`
