* 概要

MySQL で、テストの実行を途中で止めると、次の実行は ~Lock wait timeout exceeded~ で失敗することがある。止めたテストのトランザクションは終わらずに残り、行のロックを持ち続けている。

#+begin_src
ERROR 1205 (HY000): Lock wait timeout exceeded; try restarting transaction
#+end_src

ふつうは、クライアントの接続が切れるとセッションが終わり、コミットしていないトランザクションはロールバックされる。

#+begin_quote
If a session that has autocommit disabled ends without explicitly committing the final transaction, MySQL rolls back that transaction.

[[https://dev.mysql.com/doc/refman/8.4/en/innodb-autocommit-commit-rollback.html][MySQL 8.4 Reference Manual - autocommit, Commit, and Rollback]]
#+end_quote

~BEGIN~ や ~START TRANSACTION~ で始めたトランザクションも、終わるまでは autocommit が無効になっているので、この場合に当てはまる。

#+begin_quote
With START TRANSACTION, autocommit remains disabled until you end the transaction with COMMIT or ROLLBACK.

[[https://dev.mysql.com/doc/refman/8.4/en/commit.html][MySQL 8.4 Reference Manual - START TRANSACTION, COMMIT, and ROLLBACK Statements]]
#+end_quote

残るのは、セッションが終わっていないときである。テストのプロセスが接続を開いたまま生き残っていたり、重いクエリの実行中で、サーバーがクライアントの切断にまだ気づいていなかったりすると、トランザクションとロックが残る。

残ったトランザクションは、 ~information_schema.INNODB_TRX~ で、それを持っているスレッドの番号と開始時刻を引ける。

#+begin_quote
The INNODB_TRX table provides information about every transaction currently executing inside InnoDB, including whether the transaction is waiting for a lock, when the transaction started, and the SQL statement the transaction is executing, if any.

[[https://dev.mysql.com/doc/refman/8.4/en/information-schema-innodb-trx-table.html][MySQL 8.4 Reference Manual - The INFORMATION_SCHEMA INNODB_TRX Table]]
#+end_quote

その番号を ~KILL~ に渡して接続を切ると、セッションが終わり、トランザクションはロールバックされる。更新は元に戻り、次回の実行は通るようになる。

#+caption: 残ったトランザクションを探して終わらせる
#+begin_src sql
SELECT trx_mysql_thread_id, trx_started FROM information_schema.INNODB_TRX ORDER BY trx_started;
KILL 11; -- 上で見つけた trx_mysql_thread_id
#+end_src
