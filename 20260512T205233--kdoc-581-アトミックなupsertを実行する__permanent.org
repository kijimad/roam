* 概要

DBレベルのアトミックな ~upsert~ は、PostgreSQLでは ~ON CONFLICT~ を用いてこのように書く。

#+begin_src sql
INSERT INTO users (email, name)
VALUES ('user@example.com', 'admin')
ON CONFLICT (email) DO UPDATE SET name = 'admin';
#+end_src

2クエリ ~SELECT~ + (~INSERT~ or ~UPDATE~) にするなどでアトミックでなくなると、同時に実行したときに両方とも ~INSERT~ してしまうことになり安全ではない。

ORMにあるような ~upsert~ はこのクエリを発行することが多いが、同じテーブル限定などの使用条件があり、2クエリにフォールバックするときがある。
