KDOC 651: pg_stat_statements は COMMIT のときに走る処理の時間を記録しない

概要

Aurora PostgreSQL の Performance Insights で、COMMIT が DB load(AAS)の多くを占めていたのに、Avg latency は 0 ms だった。実行するクエリ的にも、高頻度の明示的なトランザクション内での書き込みで時間がかかっているように見えた。

COMMIT に時間がかかったとき、pg_stat_statements はその時間を記録するのかを確認する。

COMMIT をわざと遅くして確かめる。遅延制約トリガーは COMMIT のときに走るので、その中で1秒待つ。COMMIT をはさんだ時間と、pg_stat_statements が COMMIT に記録した時間を比べる。準備と計測は、あとの対照実験と共通にする。 

CREATE EXTENSION pg_stat_statements;
CREATE TABLE t (id int);

-- COMMIT のときに1秒かかる処理を作る
CREATE FUNCTION slow_at_commit() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_sleep(1);
  RETURN NULL;
END $$;

SELECT pg_stat_statements_reset() IS NOT NULL AS reset;

BEGIN;
INSERT INTO t VALUES (1);
-- COMMIT の直前の時刻を覚える
SELECT set_config('my.t0', clock_timestamp()::text, false) IS NOT NULL AS saved;
COMMIT;

-- COMMIT をはさんだ時間(サーバーの時計で測る)
SELECT clock_timestamp() - current_setting('my.t0')::timestamptz AS commit_time;

-- pg_stat_statements が記録した時間
SELECT format('%s : %s ms', query, round(total_exec_time::numeric, 3)) AS recorded
FROM pg_stat_statements
WHERE query IN ('COMMIT', 'INSERT INTO t VALUES ($1)');

<<setup>>
CREATE CONSTRAINT TRIGGER t_slow
AFTER INSERT ON t
DEFERRABLE INITIALLY DEFERRED
FOR EACH ROW EXECUTE FUNCTION slow_at_commit();

COMMIT をはさんだ時間は約1秒なのに、pg_stat_statements が COMMIT に記録した時間は 0.000 ms である。

これだけでは、pg_stat_statements がトリガーの時間を記録しないだけ、という可能性が残る。そこで対照実験として、トリガーを遅延させず、INSERT の文の終わりで走らせる。それ以外は同じ条件にする。 

<<setup>>
-- 対照: DEFERRABLE INITIALLY DEFERRED を外す。INSERT の文の終わりで走る
CREATE CONSTRAINT TRIGGER t_slow
AFTER INSERT ON t
FOR EACH ROW EXECUTE FUNCTION slow_at_commit();

今度は COMMIT をはさんだ時間はほぼ 0 で、pg_stat_statements は INSERT に約1秒を記録した。同じトリガーでも、INSERT の中で走れば記録され、コミット処理の中で走れば記録されなかった。記録されないのはトリガーだからではなく、コミット処理だからに見える。
