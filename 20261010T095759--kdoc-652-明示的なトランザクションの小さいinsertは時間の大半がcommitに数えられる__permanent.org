* 概要

Aurora PostgreSQL の Performance Insights で、Top SQL の1位が COMMIT だった。SELECTのクエリは集計の項目として出ていたが、DMLのクエリは出てないように見えた。アプリケーションは RLS のために、すべてのクエリを BEGIN〜COMMIT のトランザクションで実行していた。書き込みの時間は、どんな書き方のときに COMMIT の行に出るのかを確かめる。

pgbench で INSERT を流しながら、別のセッションが 10 ms ごとに pg_stat_activity でアクティブなセッションの文を数える。2つのセッションが同時に要るので、この実験は pgpg のプロキシを通さず、PostgreSQL に直接つなぐ。

#+caption: 標本の実験: 書き込みながら、10 ms ごとにアクティブなセッションの文と待機イベントを数える
#+begin_src shell :results output verbatim
  # 書き込む側と標本を取る側の2つのセッションが同時に要るので、pgpg のプロキシを通さず PostgreSQL に直接(15433)つなぐ
  sample() {
    psql -h localhost -p 15433 -U postgres -d postgres -qAt -F ' | ' <<'SQL'
  CREATE TABLE samples (query text, wait text);
  DO $$
  BEGIN
    FOR i IN 1..400 LOOP
      PERFORM pg_stat_clear_snapshot();
      INSERT INTO samples
      -- 待機イベントがなければ CPU で動いている
      SELECT query, coalesce(wait_event_type || ':' || wait_event, 'CPU')
      FROM pg_stat_activity
      WHERE application_name = 'pgbench' AND state = 'active';
      PERFORM pg_sleep(0.01);
    END LOOP;
  END $$;
  SELECT query, wait, count(*) FROM samples GROUP BY 1, 2 ORDER BY 3 DESC;
  DROP TABLE samples;
  SQL
  }

  # $1: 説明、$2: pgbench に流す SQL、$3: pgbench のオプション
  run() {
    echo "== $1"
    docker exec pgpg-postgres-1 psql -U postgres -qAt \
      -c "DROP TABLE IF EXISTS w" -c "CREATE TABLE w (id int, pad text)" \
      -c "CREATE INDEX ON w (id)" -c "CREATE INDEX ON w (pad)" 2>/dev/null
    printf "$2" | docker exec -i pgpg-postgres-1 sh -c 'cat > /tmp/bench.sql'
    out=$(mktemp)
    # 拡張プロトコル(-M extended)で書き込む
    docker exec pgpg-postgres-1 pgbench -U postgres -n -M extended $3 \
      -f /tmp/bench.sql postgres > "$out" 2>/dev/null &
    sleep 0.3
    sample
    wait
    grep 'latency average' "$out"
    rm -f "$out"
  }

  run "小さい INSERT を明示的なトランザクションで(4並列、5秒)" \
      'BEGIN;\nINSERT INTO w VALUES (1, md5(random()::text));\nCOMMIT;\n' "-c 4 -T 5"
  run "小さい INSERT を自動コミットで(4並列、5秒)" \
      'INSERT INTO w VALUES (1, md5(random()::text));\n' "-c 4 -T 5"
  run "50万行の INSERT を明示的なトランザクションで1回" \
      'BEGIN;\nINSERT INTO w SELECT i, md5(i::text) FROM generate_series(1, 500000) i;\nCOMMIT;\n' "-c 1 -t 1"
  docker exec pgpg-postgres-1 psql -U postgres -qAt -c "DROP TABLE w"
#+end_src

- 小さい INSERT を明示的なトランザクションで繰り返すと、標本の約98%が COMMIT だった。COMMIT の標本のほとんどは、WAL の確定を待つ IO:WalSync と LWLock:WALWrite だった
- 同じ INSERT を自動コミットにすると、標本はすべて INSERT になった。待機イベントの内訳も、1回あたりの時間も変わらない
- 50万行の INSERT を1回でコミットすると、標本のほとんどは INSERT の CPU で、COMMIT は1回だけだった。INSERT の最中にも IO:WalWrite と IO:WalSync が出ている。

#+begin_quote
WalSync: WALファイルが永続的ストレージに達するのを待機しています。

WALWrite: WALバッファがディスクに書き込まれるのを待機しています。
